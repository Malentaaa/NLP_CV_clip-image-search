# Поиск изображений по текстовому запросу
## 🔍 Цель проекта

Разработать модель, которая получает векторное представление изображения и текстового запроса и возвращает вероятность соответствия изображения тексту (значение от 0 до 1).         
Модель должна определять, насколько описание подходит к изображению, и использоваться в системе поиска.

---

## 🧩 Задачи проекта

- Изучить и проанализировать датасет изображений и текстовых описаний
- Cформировать целевую переменную
- Очистить данные с учетом юридических ограничений (исключение изображений с детьми)
- Выполнить векторизацию изображений с использованием предобученной модели компьютерного зрения
- Выполнить векторизацию текстов с использованием мультимодальной модели
- Оценить качество модели (ROC-AUC, F1)
- Реализовать демонстрационный поиск

## 💬 Описание данных

`train_dataset.csv` — обучающая выборка:
- `image` — имя файла изображения
- `query_id` — идентификатор текстового описания
- `query_text` — текст запроса

`train_images`/ — изображения для обучения

`CrowdAnnotations.tsv` — оценки соответствия изображения и текста, полученные от пользователей:
- доля согласившихся
- количество согласившихся
- количество несогласившихся

`ExpertAnnotations.tsv` — оценки соответствия от трёх экспертов (шкала 1–4)

`test_queries.csv` — тестовые запросы:
- текст запроса
- релевантное изображение

`test_images`/ — изображения для тестирования модели

## ⚙️ Моделирование

### Zero-shot CLIP
Для задачи поиска изображений по текстовому описанию требуется модель, которая способна сопоставлять текст и изображения в общем семантическом пространстве.

Модель CLIP (Contrastive Language–Image Pretraining) обучена на большом наборе пар «изображение–текст» и позволяет:
- кодировать изображение и текст в одно общее векторное пространство;
- измерять степень соответствия через косинусное сходство;
- использовать модель без дополнительного обучения (подходит для PoC).

Train ROC-AUC: 0.94        
Valid ROC-AUC: 0.94       
Лучший порог: 0.2864         
F1 на train: 0.6583            

### Alignment Head поверх Clip

Чтобы привести модель к бизнес-интерпретируемому скору, поверх замороженных эмбеддингов CLIP обучается лёгкая линейная модель Ridge
Train ROC-AUC: 0.97            
Valid ROC-AUC: 0.94            
Лучший порог: 0.4361         
Train F1: 0.7952         
Valid F1: 0.7157         

Качество значительно выросло F1 выросло с 0.66 до 0.71.

### Исследование «слепых зон» модели Hard Negatives

![2723477522_d89f5ac62b](https://github.com/user-attachments/assets/5469bf84-0a22-4efd-8efc-5fa1d0ca4109)

в ходе экспериментов по тестовому изображению выяялено, что модель CLIP:
- почти не различает кто кого догоняет. Она понимает - "есть два пса, один большой, один маленький", но не понимает направление действия.
- видит "собак", но почти не различает точное количество. Скорее реагирует на наличие объекта, чем на счёт.
- хорошо различает визуальные атрибуты (цвет собак)
- приемлемо для поисковой системы в фотохостинге

### LoRA

LoRA позволяет дообучить модель аккуратно и без изменения всех параметров. Цель эксперимента — понять, улучшится ли качество сопоставления изображений и текста по сравнению с базовой моделью.

Датасет небольшой и сильно несбалансирован, была использована минимальная конфигурация LoRA с осторожными гиперпараметрами: две эпохи обучения, пониженный learning rate, увеличенный batch size и заморозка параметра logit_scale.

Train ROC-AUC: 0.97          
Valid ROC-AUC: 0.94              
Лучший порог: 0.4887             
Train F1: 0.7976            
Valid F1: 0.7185                  

Минимальная конфигурация LoRA не привела к существенному росту ROC-AUC, однако позволила немного улучшить F1-метрику на валидации до 0.72. Это говорит о том, что аккуратная адаптация представлений возможна даже на небольшом датасете, однако существенного прироста качества без увеличения объёма данных ожидать не следует.

### Индекс FAISS для поиска

Когда изображений мало, можно искать подходящую картинку простым перебором — сравнивать запрос с каждым изображением по очереди. Но если изображений станет тысячи или миллионы, такой поиск будет слишком медленным.

Чтобы сделать систему масштабируемой, была использована библиотека FAISS — инструмент для быстрого поиска похожих векторов.
